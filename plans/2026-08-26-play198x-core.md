# `play198x-core` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `play198x-core` — the published library that opens a retro media file from any of three container shapes, identifies it from its bytes, and yields either an RGBA image or a ProTracker module that plays.

**Architecture:** One new workspace at `play198x/play198x` holding one library crate with five modules — `container`, `probe`, `decode`, `engine`, `metadata`. Decoding is delegated entirely to the Format198x crates; palettes come from `mediaspec198x`; the engine is a pull-based frame source that never owns an audio device.

**Tech Stack:** Rust 2024, `zip` for archive reading, seven `format198x-*` crates, `mediaspec198x`. No UI, no audio device, no async.

**Spec:** [`../specs/2026-08-25-data-driven-core-design.md`](../specs/2026-08-25-data-driven-core-design.md)

**Depends on:** [`198x/docs/plans/2026-08-26-org-prefixed-crate-names.md`](../../../docs/plans/2026-08-26-org-prefixed-crate-names.md) — **execute that plan first.** Every crate name below is the post-rename name, and `mediaspec198x` does not exist on crates.io until its Task 4.

## Global Constraints

Every task's requirements implicitly include this section.

- **Rust 2024 edition**, workspace `rust-version = "1.87"`.
- **`play198x-core` is `publish = true` and independently versioned** — `version = "0.1.0"` written literally, never `version.workspace = true`. Binding: `studio198x-authoring.md` clause 5, and `emu198x/emu198x#1214` for what getting it wrong costs.
- **No panic reachable from any container, probe, or decode path.** Typed errors only. `unsafe_code = "forbid"`; `unwrap_used` and `expect_used` denied outside `#[cfg(test)]`.
- **No global mutable state, no main-thread assumption, no lazy global init.** A thumbnailer runs inside somebody else's process, possibly several at once, and is spawned once per file.
- **The engine never owns an audio device**, and `render` allocates nothing.
- **No media files in the repository, ever.** Tests build synthetic inputs in code; anything needing real media is `#[ignore]`d and reads a path from an environment variable.
- **Every test asserts a specific value or a specific error variant** — never a bare `is_ok()`, `is_err()`, or a count where the value is what matters. The Format198x round found two tests that passed without measuring what they claimed, and one hid a defect for a whole fix round.
- **Conventional commits.** Titles describe the effect; bodies explain why and record failed approaches.
- **Never bypass a commit hook or disable a test to make something pass.**

## Dependencies — approve before Task 1

`play198x-core` is not dependency-free; only the Format198x crates are. The whole list, stated once:

| Crate | Why | Alternative considered |
|---|---|---|
| `zip` | ZIP container reading. | Hand-rolling one still needs a DEFLATE implementation, so the dependency is not avoided, only made worse. |
| `format198x-*` (seven) | The decoders. | None — this is what Format198x is for. |
| `mediaspec198x` | Palettes for the fixed-palette machines. | Duplicating palettes here trips `shared-media-spec.md`'s own drift trigger. |

**No audio dependency, deliberately.** The engine produces `f32` frames on demand; the shells own `cpal` and WebAudio. That is exactly what lets the differential harness compare numerically instead of capturing a live device.

**No libxmp binding.** Task 10's harness shells out to the installed `xmp` CLI from an `#[ignore]`d test — the pattern Format198x already uses for its netpbm cross-checks — rather than taking an FFI dependency to compare against.

## The `to_rgba8` ruling this plan works under

The spec says every image crate exposes `T::to_rgba8()`. **The shipped crates do not, and must not.** RGBA needs a palette; palettes belong to `mediaspec198x` under `shared-media-spec.md`; and a Format198x crate cannot depend on it without breaking the dependency-free rule that is the stated reason Format198x exists. Re-deriving palettes inside a format crate instead is that decision's own drift trigger, verbatim.

So the format crates stay **index-only** — `pixel()`, `bit_pair()`, `color_index()`, which is what they already expose — and `play198x-core::decode` converts, holding the palette. ILBM needs no palette lookup at all: its CMAP chunk carries one.

The naming plan's Task 4 Step 7 writes this into the decision record, superseding the spec's clause.

## Two open questions this plan settles

The spec left both to the implementation plan, and both are settled here rather than deferred again.

- **SCR identification is weak.** A 6912-byte file is *probably* a SCR and the length is the only signal. `probe` returns a confidence alongside the format (Task 4), never a bare assertion.
- **Sample-rate conversion quality.** Nearest-neighbour, because it is closest to what Paula does. Anything better is a later, measured change (Task 7).

- [ ] **Step 3: Write the error type and the public surface**

`src/lib.rs`. This is the shape every later task adds to, so get the variants' *meaning* right now even though most are unreachable yet.

```rust
//! Open, identify and render retro media.

pub mod container;
pub mod decode;
pub mod engine;
pub mod metadata;
pub mod probe;

/// Everything that can go wrong, from opening a path to decoding an entry.
///
/// Container errors say what is true rather than what is convenient. A
/// bootblock Amiga disk is **not** a corrupt ADF — it is a disk with no DOS
/// filesystem, and reporting it as corruption sends the reader looking for a
/// damaged image that does not exist.
#[derive(Debug)]
#[non_exhaustive]
pub enum Error {
    /// The path could not be read.
    Io(std::io::Error),
    /// The container opened, but this entry is not in it.
    NoSuchEntry { path: String },
    /// The bytes are not any format this crate recognises.
    Unrecognised,
    /// A decoder rejected the bytes. Carries the decoder's own message.
    Decode { format: probe::Format, what: String },
    /// The container itself is malformed.
    Container { what: String },
    /// The disk has no DOS filesystem — a bootblock or non-DOS disk, which is
    /// a different thing from a damaged one.
    NotAFilesystem,
}
```

Implement `Display` and `std::error::Error` for it, and `From<std::io::Error>`.

```rust
pub struct Entry { pub path: String, pub len: u64 }

pub enum Container {
    Plain(PathBuf),
    /// The whole archive, in memory. A `ZipArchive` is built over a cursor per
    /// call rather than held, so `read` needs only `&self` and no interior
    /// mutability — the access pattern is a handful of entries, not a stream.
    Zip(Vec<u8>),

}

impl Container {
    pub fn open(path: &Path) -> Result<Self, Error>;
    pub fn entries(&self) -> Result<Vec<Entry>, Error>;
    pub fn read(&self, entry: &str) -> Result<Vec<u8>, Error>;
}
```

```rust
fn a_zip_enumerates_its_entries_and_reads_one_back() {
    let zip = build_zip(&[("a/tune.mod", &[1u8, 2, 3]), ("b/screen.scr", &[4u8; 10])]);
```

### Task 4: Identify a format from its bytes

**Files:**
- Create: `crates/play198x-core/src/probe.rs`
- Test: `crates/play198x-core/tests/probe.rs`

**Interfaces:**
- Consumes: nothing.
- Produces:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[non_exhaustive]
pub enum Format { Scr, Koala, ArtStudio, Ilbm, ProTracker }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Confidence {
    /// A magic number or structural signature identifies this and nothing else.
    Certain,
    /// The bytes are consistent with this format, but the evidence is weak —
    /// a length or a load address that other things also have.
    Probable,
}

pub fn identify(bytes: &[u8]) -> Option<(Format, Confidence)>;
```

Task 5 dispatches on `Format`; a shell shows `Probable` differently.

- [ ] **Step 1: Write the failing tests, one per format**

Each asserts the exact `(Format, Confidence)` pair, never just that something was returned.

```rust
#[test]
fn a_module_is_identified_by_its_magic_with_certainty() {
    let m = synthetic_module();          // reuse the shape from the MOD crate's tests
    assert_eq!(identify(&m), Some((Format::ProTracker, Confidence::Certain)));
}

#[test]
fn a_6912_byte_file_is_only_probably_a_screen() {
    assert_eq!(identify(&vec![0u8; 6912]), Some((Format::Scr, Confidence::Probable)));
}

#[test]
fn nothing_is_identified_from_an_empty_input() {
    assert_eq!(identify(&[]), None);
}
```

- [ ] **Step 2: Run and watch them fail**

- [ ] **Step 3: Implement, strongest signal first**

Order matters — a weak test must never shadow a strong one.

| Format | Signal | Confidence |
|---|---|---|
| ProTracker | four-byte magic at offset 1080, via `format198x_commodore_amiga_mod::is_module` | `Certain` |
| ILBM | `FORM` at 0 and `ILBM` at 8 | `Certain` |
| Koala | load address `0x6000` little-endian at 0, **and** length `10003` | `Certain` |
| Art Studio | load address `0x2000` at 0, **and** length in `9002..=9009` | `Certain` |
| SCR | length exactly 6912 and nothing above matched | `Probable` |

Use each format crate's own constants — `LOAD_ADDRESS`, `FILE_LEN`, `MIN_FILE_LEN` — rather than repeating the numbers. They are `pub` for this.

- [ ] **Step 4: Pin the ordering with a test that would fail if it were wrong**

A 6912-byte file that also happens to start with `0x6000` must come back as Koala, not SCR — except 6912 is not Koala's length, so construct the real collision: assert that a Koala-length file starting with the Koala load address is `Koala` with `Certain`, and that flipping the load address alone drops it to `None`. Then assert an ILBM whose length is coincidentally 6912 identifies as `Ilbm`, not `Scr`.

- [ ] **Step 5: Never panic on hostile input**

```rust
#[test]
fn identify_never_panics_on_arbitrary_input() {
    let mut hit = std::collections::BTreeSet::new();
    for len in [0usize, 1, 2, 11, 1080, 1084, 6911, 6912, 6913, 10003] {
        for fill in [0x00u8, 0xFF, 0x55, 0xAA, 0x60, 0x20] {
            if let Some((f, _)) = identify(&vec![fill; len]) { hit.insert(format!("{f:?}")); }
        }
    }
    assert!(!hit.is_empty(), "the sweep never reached a positive identification");
}
```

The final assertion is the point. A sweep that identifies nothing proves only that nothing crashed, and would keep passing if `identify` were changed to return `None` unconditionally.

- [ ] **Step 1: Write the failing test for the Spectrum**

Assert a *specific pixel's colour*, not the buffer length. A length assertion passes for an all-black image, which is exactly what a broken palette lookup produces.

```rust
#[test]
fn a_spectrum_screen_decodes_to_its_palette_colours() {
    let mut scr = vec![0u8; 6912];
    scr[0] = 0b1000_0000;          // top-left pixel set
    scr[6144] = 0b0000_0111;       // that cell: ink 7 (white) on paper 0 (black), no bright
```

- [ ] **Step 1: Write the failing timing test**

The single most important number in the whole engine. Get it wrong and everything downstream is 20% out.

```rust
#[test]
fn a_row_lasts_speed_ticks_at_the_default_tempo() {
    // Default: speed 6, tempo 125 → tick = 2500/125 = 20 ms → row = 120 ms.
    let mut e = Engine::new(one_pattern_module(), 44_100);
    let mut buf = vec![0f32; 2];
    let mut frames = 0;
    while e.position().row == 0 { frames += e.render(&mut buf); }

```

- [ ] **Step 2: Run and watch it fail**

- [ ] **Step 3: Implement the sequencer**

Tick period is `2500 / tempo` milliseconds; a row is `speed` ticks. The order table drives pattern selection, and `song_length` bounds it — not the full 128 entries, which is a different question from the one the MOD crate's pattern-count rule answers. Read `protracker-playback-reference.md` before writing the loop.

- [ ] **Step 4: Implement Paula-rate sample playback**

```rust
// PAL Paula clock. rate = clock / (2 * period); C-2 (period 428) = 8287.14 Hz.
const PAULA_CLOCK_PAL: f64 = 7_093_789.2;
```

Nearest-neighbour resampling, per this plan's settled open question — it is closest to what Paula does, and anything better is a later, measured change. Loop points come from the sample header; a sample with a loop length above 1 word repeats, one at or below it plays once.

Sample data is `Vec<u8>` on `Sample`; use `Sample::data_i8()` for the signed view rather than casting by hand.

- [ ] **Step 5: Pin the pitch with a measurement, not an assertion about code**

```rust

    // A module whose one sample is a square wave, played at period 428.
    let mut e = Engine::new(square_wave_module(428), 44_100);
    let mut buf = vec![0f32; 44_100 * 2];
    e.render(&mut buf);
    let hz = dominant_frequency(&buf);   // zero-crossing count over a known window

```

**Measure over at least 100 ms.** A 2.5 ms window cannot resolve a 129 Hz carrier and quantises to 0, 200 or 400 Hz — that mistake was made on 2026-08-25 and cost a wrong conclusion about the mixer.

- [ ] **Step 6: Prove `render` allocates nothing**

### Task 7: The three effect dispatch tables

**Files:**
- Create: `crates/play198x-core/src/engine/effects.rs`
- Modify: `crates/play198x-core/src/engine/mod.rs`
- Test: `crates/play198x-core/tests/effects.rs`

**Interfaces:**
- Consumes: the tick loop from Task 6.
- Produces: no new public surface. Effects are internal; they are observable only through `render`'s output, which is how they must be tested.

**Read [`protracker-playback-reference.md`](../../../reference/by-topic/music-formats/protracker-playback-reference.md) before writing a line of this task.** It carries line-numbered citations into the replayer, and the arbitration order when sources disagree is: the replayer source first, libxmp second, community specs last. That order is load-bearing — the widely-cited community spec is wrong about vibrato by 20%.

- [ ] **Step 1: Write the failing test for the rate that catches the classic bug**

```rust
#[test]
fn a_per_tick_effect_runs_speed_minus_one_times_per_row() {
    // Volume slide down (A0x) from full volume, speed 6.
    // Six ticks per row, but the row's first tick fetches the row — so the
    // slide applies five times, not six.
    let mut e = Engine::new(volume_slide_module(0x0A, 0x01, 6), 44_100);
    render_one_row(&mut e);
    assert_eq!(e.debug_channel_volume(0), 64 - 5, "slide must apply speed-1 times");
}
```

A single dispatch table, or a loop that runs `speed` times, produces 58 here instead of 59 — a silent 20% error in *every* per-tick effect at the default speed. Expose `debug_channel_volume` behind `#[doc(hidden)]` rather than making the whole mixer state public.

- [ ] **Step 2: Run and watch it fail**

- [ ] **Step 3: Implement the three tables**

| Table | When it runs | Effects |
|---|---|---|
| `prefx_tab` | note tick, **before** the period is set | `3` and `5` tone portamento, `9` sample offset |
| `morefx_tab` | note tick after setup, or a row with no note | `9` `B` `C` `D` `E` `F` |
| `fx_tab` | every tick that does **not** fetch a row | `0` `1` `2` `3` `4` `5` `6` `7` `A` `E` |

Three tables, not one. This is not gold-plating: effect `9` appears in *two* of the note-tick tables, which a single switch structurally cannot express. Model the dispatch as three functions over the same channel state, called at the three points in the tick loop.

- [ ] **Step 4: Write one test per effect, each measuring the effect's own observable**

Fixtures are **synthetic single-effect modules generated in code** — one held note plus one effect. Real music confounds the measurement: a first attempt on 2026-08-25 measured a real module's vibrato and got the row rate instead, because at speed 5 the 0.100 s row period dominated the envelope.

Measure the right observable for each kind:

- **Pitch effects** (`0` arpeggio, `1`/`2` portamento, `3` tone portamento, `4` vibrato) — track pitch per waveform cycle, never by autocorrelation over a window. Autocorrelation locks onto multiples and reported speed 10 as *slower* than speed 5 on 2026-08-25.
- **Volume effects** (`5` `6` `7` `A` `C`) — the envelope.
- **Position effects** (`B` `D` `F`) — `Position`, directly.
- **`9` sample offset** — the first frame's amplitude, against a sample whose value at the offset differs from its start.

For vibrato specifically, the expected depth-and-rate relation is `(x × (ticks − 1))/64` cycles per division, **not** `(x × ticks)/64`. The community spec's version is a 20% error at the default speed, and libxmp and libopenmpt disagree with each other here, so a consensus of implementations is not available as an authority. The replayer source arbitrates.

- [ ] **Step 5: Cover `E`-command sub-effects**

`E` is sixteen effects behind one nibble. Cover at minimum `E1`/`E2` fine portamento, `E9` retrigger, `EA`/`EB` fine volume slide, `EC` note cut, `ED` note delay, `EE` pattern delay. Each gets its own test asserting its own observable.

```bash

git add -A && git commit -m "feat: run ProTracker's effects from its three dispatch tables"
```

## What this plan does not build

Named so the next plan's scope is unambiguous, not as an apology.

- **The shells.** `play198x-gui` (GPUI) and `play198x-web` (wasm-bindgen) are the next plan. This one ends with a library and no way to look at it — deliberately, because the shells are thin by design and there is nothing to make thin until the core works.
- **SID, AY, NSF, SAP.** Blocked on an Emu198x decision about publishing the chip crates (`emu198x/emu198x#1214`). No amount of work here reaches a `.sid`.
- **Animation** — ANIM, FLI/FLC. Needs a field-rate framebuffer this slice has no use for.
- **The CLI and the FFI surface.** The constraints they impose are held from the first commit (no global state, no panic, cold-start budget), but neither is built here.
